# Secret Vault Bootstrap, Git Activation Journal, and Lockfile Caching

## Decision

1. **Secret vault bootstrap:** Encrypted secrets live in SQLite (`encrypted_secret_blobs`) encrypted via AES-256-GCM with per-secret AAD (`<secret_name>:v<key_version>`). The 256-bit master key is never stored inside SQLite or the Git Workspace. Key sources, in precedence order: `DASH_MASTER_KEY` (Administrator-provided, never persisted); `DASH_MASTER_KEY_FILE` (a key file at an Administrator-chosen path, ideally a separate mount outside the data directory); `DASH_VAULT_PASSPHRASE` (`<data_dir>/vault.key` is stored wrapped by an Argon2id passphrase-derived KEK with AES-256-GCM, and a legacy plaintext key file is re-wrapped in place). A plaintext `<data_dir>/vault.key` (created atomically with mode `0600`) co-locates key and ciphertext without an additional protection boundary (§5.2), so the vault refuses it unless the Administrator opts in explicitly with `DASH_ALLOW_COLOCATED_VAULT_KEY=1` (unattended single-host or throwaway use; the repository's `.cargo/config.toml` sets it for development and test runs); with the opt-in the vault reports `unprotected_colocated` and `dash doctor` warns. OS-keychain integration remains open (§19.5). Known secrets are registered with a thread-safe `Redactor` that scrubs plaintext from logs, trace spans, errors, and HTTP responses.
2. **Git activation journal & crash recovery:** Draft activation records transitions (`started` -> `committed` -> `activated` -> `pushed`) in SQLite `activation_journal`. On startup, `DraftManager::initialize` reconciles any incomplete journal against Workspace `HEAD` so crashed activations never leave a split-brain active Generation. Remote push failure marks `git_sync_state = unsynced` while keeping the locally committed and activated Generation operational for subsequent `dash git sync` retries.
3. **Offline lockfile reproducibility:** External Git packages declared in `packages.toml` are resolved transitively to exact Git commit SHAs and SHA-256 tree digests in `packages.lock`, with package trees cached under `<data_dir>/package_cache/<tree_digest>/` so restarts operate completely offline without re-fetching moving refs.
